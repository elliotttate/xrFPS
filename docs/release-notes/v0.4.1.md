# xrFPS 0.4.1

A fix for a crash that xrFPS caused in other OpenXR API layers installed
alongside it.

## Fixed

- **Layers below xrFPS could crash the application during startup.** To decide
  whether to enable Meta's performance-metrics extension, the layer asked the
  next layer down for `xrEnumerateInstanceExtensionProperties` *before* calling
  `nextCreateApiLayerInstance`. The OpenXR loader only hands a layer its
  downstream dispatch once its own `xrCreateApiLayerInstance` has returned, so
  at that moment the layer below has nothing to forward to — the loader
  specification is explicit that a layer sets up its dispatch table only
  *"if the call passes"*. A layer that assumed the documented order and
  dereferenced its not-yet-assigned pointer took the whole application down
  with an access violation.

  xrFPS no longer asks. It requests the extension and lets instance creation
  answer: when the runtime does not have it the call fails, and xrFPS retries
  with exactly the extension list the application asked for. Runtimes that do
  support it are unaffected, and the HUD keeps its runtime-native timing.

  The visible symptom was a hard crash on launch for anyone running xrFPS
  together with another API layer — an OBS mirror layer, a capture tool, an
  upscaler — with no error message beyond an access violation at address zero.

## Install or update

The Control Center offers this update in the app. To install by hand, download
and run `xrFPS-0.4.1-Setup.exe`, or extract the portable ZIP complete.
