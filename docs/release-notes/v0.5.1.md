# xrFPS 0.5.1

One fix: the Control Center crashed on startup on any machine running
Windows in light mode — which is how Windows ships. If 0.5.0 (or any earlier
version) never opened for you, this is the release that fixes it.

## Fixed

- **Light-mode machines crashed with a `XamlParseException` before the window
  existed.** The app's theme table defined resources only for `Dark` and
  `HighContrast`. XAML theme lookup falls back from the active theme to
  `Default`, but never sideways into a sibling theme — so on a light-mode
  machine `RootBackgroundBrush` (the first `ThemeResource` the window parses)
  resolved against `Light`, fell back to a `Default` that did not exist, and
  took the app down. Dark-mode machines — including every machine xrFPS was
  developed on — never hit it.

  The dark theme table is now keyed `Default`, making it the universal
  fallback, and the app declares `RequestedTheme="Dark"` outright, since its
  design is dark. High-contrast mode still wins, as Windows guarantees.

  In 0.4.1 this crash was invisible; 0.4.2's new startup reporting is what
  produced the dialog naming `RootBackgroundBrush` — and the field reports
  that made this fix a same-day one.

## Install or update

Use *Check for updates* inside the Control Center, or download and run
`xrFPS-0.5.1-Setup.exe` — it upgrades an existing install in place. The
installer is unsigned, so SmartScreen shows a warning: choose
*More info → Run anyway*, or verify your download against `SHA256SUMS.txt`.
