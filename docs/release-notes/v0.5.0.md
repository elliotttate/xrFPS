# xrFPS 0.5.0

The HUD can now live anywhere — eight fixed controller mounts, head locked, or
a floating panel that softly follows below your view. And it stops billing its
own rendering cost to the game it is measuring.

## New: placement presets

- **Controller available**: the original adaptive underside stays the default,
  joined by eight fixed mounts around either controller (tilted undersides,
  palm side, top), a head-locked panel, and a floating follow panel that lags
  gently below your view instead of being glued to every head tremor.
- **Controller unavailable**: an independent fallback profile — follow panels
  (bottom, left, or right), head locked, three fixed in-room anchors, or
  hidden. Hidden is the default so xrFPS stays flip-to-summon; pick another
  profile for an always-on readout, including in apps that never bind
  controllers at all.
- Controller-attached placements keep the flip-to-show gesture; head-locked
  and follow placements stay visible while selected. Everything is in the
  Control Center and applies live to a running game.

## More honest numbers

- **The HUD no longer measures itself.** The frame interval containing a HUD
  refresh spans the overlay's own raster and swapchain work, so its cost was
  being billed to the application as a spike at exactly the refresh cadence.
  Average FPS barely moved, but 1% low and ON TGT — the tail metrics — took
  the damage. That interval is excluded from the statistics again, and the
  overlay still reports its own slow refreshes in the diagnostics.
- The repaint itself got four times cheaper (1.57 ms → 0.37 ms), with all
  rendered test images byte-identical.
- The target period now uses a low percentile of the sample window instead of
  its outright minimum, so one freak short reading no longer becomes the
  target everything is scored against for the next 90 frames.
- ON TGT reads the same one-second window as the FPS and frametime rows, so
  stutter stops showing long after the rate has recovered.

## Fixed

- A controller the runtime had lost could freeze the panel in mid-air: poses
  are now required to be tracked, not merely valid, before they anchor the
  HUD, and tracking loss hands over to the fallback placement.
- `F10` is only read while the game holds focus, defaults to off, and forces
  visibility without overriding the placement — it no longer yanks a
  controller-mounted panel in front of your face.
- A failed D3D12 upload could leave a half-created swapchain behind and crash
  the next frame; partial failures now unwind cleanly and creation stops
  retrying after three attempts.
- The SteamVR timing source releases its OpenVR connection on shutdown (only
  when it was the one to open it).
- A graph with no room to draw says why instead of vanishing.

## Install or update

Use *Check for updates* inside the Control Center, or download and run
`xrFPS-0.5.0-Setup.exe` — it upgrades an existing install in place. The
installer is unsigned, so SmartScreen shows a warning: choose
*More info → Run anyway*, or verify your download against `SHA256SUMS.txt`.
